# 走査のゲートが、C ソースを 1 本も持たない gem を候補に入れる

## 課題

`tools/scan_popular_gems.rb` の `[1]`(R10 ゲート通過・コーパス未収載 = **追加候補**)に、
**C のソースを 1 本も持たない gem が混ざる。** gemspec が `extensions` を宣言していれば
ゲートを通るためである。

ランク 501〜1500 の走査(2026-09-12)で `[1]` に出た 43 件のうち、表の `ext .c/.h` 欄が
**`0/0`** だったもの:

| gem | 実態(2026-09-13 に `build_load` で確認) |
|---|---|
| commonmarker 2.10.0 | Rust 拡張(`Cargo.toml`) |
| prometheus-client-mmap 1.6.1 | Rust 拡張(`Cargo.toml`) |
| sass-embedded 1.104.0 | Dart Sass の実行ファイルを取得する Rakefile |
| ruby-debug-ide 0.7.5 | 依存を入れる `mkrf_conf.rb` |
| executable-hooks 1.7.1 | ラッパーを置くだけの extconf |
| libv8 8.4.255.0.1 | V8 のビルド済み成果物を扱う |

**43 件中 6 件(14%)である。** どれも C コンパイラが仕事をする対象ではない。

## 影響

**候補の供給を多く見積もる。** 「ビルドできる gem を 100 件」の見通しは `[1]` の件数から
立てており、ランク 501〜1500 の 43 件は**実質 37 件**だった。

**検証の手間を無駄にする。** この 6 件は `build_load` まで流して初めて
「C が無い」と分かった。1 件あたり数分で、`libv8` のように取得が重いものもある。

## 受け入れ条件

- `[1]` に入るのは **C のソース(`.c`)を 1 本以上持つ gem だけ**になる
- **`extensions` を宣言しているが C ソースが 0 件の gem は、黙って捨てずに別のグループへ**振り分け、
  理由(Rust の `Cargo.toml` がある、Rakefile だけ、など)を残す。
  「なぜ X が候補に無いか」に答えられること
- ランク 501〜1500 を再走査し、`[1]` が **43 → 37 件**になり、落ちた 6 件が上の表と一致する
  ことを実測で示す(**判定の変化はこの 6 件だけ**であること)
- `rake test` が 0 failures

## 着手前に確かめること

- **ヘッダだけの gem(`.h` はあるが `.c` は無い)をどう数えるか**を決める。
  Ruby 拡張として `.h` だけで成立することは無いはずだが、実測で確かめてから線を引くこと
- `scan-metadata-prefilter-1` の第 1 段は、`files:` を見て**全文を取る価値があるか**を
  判定している。**同じ情報で**この振り分けもできるので、そこに寄せられるか検討すること
