# 128 ビット整数の除算・剰余・ビット演算を実装する

## 課題

`__int128` / `unsigned __int128` は乗算・加減算・比較・変換・シフト・値渡し・値返しまで
実装済みだが、**除算(`/`)・剰余(`%`)・ビット演算(`&` `|` `^`)が診断エラー**である。
2026-08-27 にこのホスト(WSL2 / gcc 14.2)で 5 演算子すべてを実測した:

```c
int main(void) {
  __int128 a = 100, b = 7;
  __int128 q = a / b;      /* ここを % & | ^ に置き換えた 5 通り */
  return (int)q;
}
```

| 演算子 | rubycc | gcc |
|---|---|---|
| `/` | `error: '/' on 128-bit integers is not supported yet` | 成功 |
| `%` | `error: '%' on 128-bit integers is not supported yet` | 成功 |
| `&` | `error: '&' on 128-bit integers is not supported yet` | 成功 |
| `\|` | `error: '\|' on 128-bit integers is not supported yet` | 成功 |
| `^` | `error: '^' on 128-bit integers is not supported yet` | 成功 |

診断は `lib/rubycc/ir/generator.rb` の `gen_int128_arith` が一箇所で出している
(`INT128_OP_SPELLINGS`)。単項マイナス・複合代入・`++`/`--`・可変長引数渡しも
それぞれ別の「not supported yet」を持つ。

**この 5 件は難易度が同じではない。** ビット演算 3 件は 64 ビット半分ごとの
独立した演算なので既存の `gen_int128_add` と同じ形で書ける。除算・剰余は
多倍長除算の合成が要り、桁が違う。

## 影響

**先回り実装しない**(R11 / DESIGN 4.2)という原則の対象である。実 gem での実害は
現時点で記録が無い。過去に実害を出したのは bigdecimal の 2 件だけで、いずれも
出た時点で実装した — 値渡しは Step 94、シフトは Step 95。

放置した場合、`__int128` でビットマスクや剰余を使う gem が現れた時点でビルドが止まる。
落ち方は分かりやすい(診断が演算子を名指しする)ので、切り分けの負担は小さい。

## 受け入れ条件

**ビット演算と除算・剰余は別の PR に分ける**(粒度が違うため。`issues/README.md` の
「1 PR に収まること」)。

- `&` `|` `^` が両ターゲット(x86-64 / AArch64)で gcc 差分実行オラクルと一致する。
  符号あり・符号なしの両方、および両半分にまたがるビットパターンを含む
- `/` `%` が同じくオラクルと一致する。**符号の組み合わせ 4 通り**と、
  除数が 64 ビットに収まる場合・収まらない場合、`INT128_MIN / -1` の境界を含む
- 実装した演算子が `INT128_OP_SPELLINGS` の診断経路から外れ、
  **未実装のまま残る演算子は引き続き診断される**ことをテストで固定する
- `rake test` が 0 failures
